# Run `2026-11-26_main`: the app model re-fitted with the fp32 CLIP text tower

**What changed:** only the text tower used to build the cached label embeddings, from the 8-bit export
(`text_model_quantized.onnx`) to the full-precision one (`text_model.onnx`). The vision tower, prompts,
data, splits, seed and config (`configs/main.yaml`) are identical to `2026-09-16_main`. Everything
fitted on val was re-fitted: probe C, hybrid weight, temperature, abstention and not-food thresholds.

**Why:** the comparison study (`2026-11-26_onnx`, [docs/COMPARISON.md](../../docs/COMPARISON.md)) found
that 8-bit text embeddings have only 0.74 cosine to fp32 and cost ~22 points of 188-way zero-shot
accuracy. The label matrix is computed once and cached, so fp32 costs nothing per request. Peak memory
for model load plus a request stays at 240 MB (the text tower is never loaded at runtime).

## Reading the trade-off

- **Better wherever the probe doesn't reach:** +22.8 points on the Commons photos, +56 points on
  Commons dishes outside the probe's 45 classes, and the fixture `dosa.jpg` is now a dosa (it was
  Aloo Paratha). The not-food guard and calibration also improved.
- **2.1 points lower on the test split.** Every test photo belongs to one of the probe's 45 classes, so
  this split rewards a model that concentrates probability on those 45. The old 8-bit text embeddings
  happened to do that, and val chose hybrid weight 1.0 (the probe decides everything inside the group).
  The fp32 zero-shot spreads probability more accurately over all 188 foods, including near-synonyms
  the accept sets don't list. The top test confusions are now chicken curry → butter chicken (28%),
  Greek salad → green salad (24%), chocolate cake → brownie (24%), club sandwich → sandwich (20%)
  and hamburger → veg burger (18%). Most of these are label-list overlap rather than visual mistakes,
  and the user fixes them with one tap (top-5 is 95.2%).
- **Fewer, more accurate answers.** The model declines more often (75.8% coverage vs 84.0%), but is
  right more often when it answers (87.5% vs 85.1%).

Model selection followed the protocol: everything chosen on val, test only scored. No test or Commons
number was used to choose anything.

## Follow-ups

1. Extend the accept sets in `backend/ml/class_mapping.json` for genuine synonyms (green salad for Greek
   salad, sandwich for club sandwich, veg burger for hamburger). This is a labelling decision, so it
   should be made by looking at the photos, not at the scores.
2. The per-channel INT8 vision model from `2026-11-26_onnx` (2.2× faster) is still not applied.
3. Re-run `e2e/run_e2e.sh` to regenerate the screenshots. It needs MongoDB, which this environment
   doesn't have.
